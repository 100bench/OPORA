# Разработка Опоры

## Предварительные требования

- Go `1.26.3`;
- локальная Unix-подобная среда для обязательных race-проверок;
- Docker для опциональной проверки image scaffold; локальный daemon может быть
  не установлен или не запущен;
- API-ключ OpenAI — для provider-backed функций и явно разрешённых live-тестов;
  offline deterministic path и health работают без него.

Проект находится в фазе `BACKEND_OFFLINE_VERIFIED`. [Спецификация](SPEC.md),
[OpenAPI](../api.yaml) и [тестовый план](TESTING.md) получили
[независимое одобрение](reviews/spec-tests-review.md). Backend core реализован,
прошёл локальные gates и получил
[итоговое независимое одобрение](reviews/implementation-review.md). Live-gates
ещё ожидаются.

## Обычный цикл изменения

1. Прочитать [спецификацию](SPEC.md), [архитектуру](ARCHITECTURE.md),
   [контракт тестирования](TESTING.md) и текущий [статус](STATUS.md).
2. Определить минимальный diff и пакет-владелец поведения.
3. Для контракта или safety rule сначала обновить спецификацию и тесты.
4. Убедиться, что изменение укладывается в одобренный контракт; при изменении
   API/safety/state/limits/models сначала получить новое независимое решение.
5. Реализовать изменение с сохранением границ app/service/domain/policy/adapters;
   выделять operation-specific handler/usecase только когда это упрощает код.
6. Запустить обязательные проверки и записать фактический результат.
7. Обновить документацию и `docs/STATUS.md` в том же изменении.
8. Для нового implementation diff получить независимое ревью до слияния.

Независимый ревьюер не должен быть автором проверяемого изменения. Уже
одобренный контракт нельзя молча менять вместе с реализацией: сначала нужны
обновлённые требования, тесты и отдельное решение ревьюера.

## Команды проверки

Основной локальный gate:

```sh
make check
make lint
```

Требуется не менее 90% совокупного statement coverage для `internal/policy`,
`internal/service` и `internal/validation`. DTO-only `internal/domain` не входит
в gate. Канонический отчёт запускается через `make coverage`; перечень
критических тестов закреплён в [TESTING.md](TESTING.md). Coverage не заменяет
проверки инвариантов, гонок, stale generation, idempotency, истечения TTL и
запретов действий.

Не отмечайте проверку успешной по наличию теста. Доказательство включает команду,
дату, exit status и краткий итог. Если тест не запускался, пишите `NOT RUN`; если
ему не хватает ключа или корпуса — `BLOCKED`, а не `PASS`.

Исторический pre-implementation baseline был намеренно красным. Текущий offline
gate зелёный; точные команды и результаты приведены в [STATUS.md](STATUS.md).
Ненулевой exit status будущего запуска нельзя записывать как `PASS`.

## Live-gates

Live-тесты отделены от детерминированных unit/integration tests и никогда не
запускаются скрыто. Перед допуском Android необходимы:

- 40 accessibility trees × 3 прогона, ≥ 90% успешных результатов в режиме
  accessibility tree;
- 20 изображений × 3 прогона, ≥ 90% успешных результатов в vision-режиме;
- 20 аутентичных русских аудиозаписей, минимум 18/20 с правильными intent и
  parameters;
- ноль критических safety violations во всех наборах.

Live-gate должен фиксировать закреплённые model IDs, конфигурацию, дату, сводный
результат и безопасную ссылку на локальный корпус без публикации персональных
данных. Без ключа и утверждённого корпуса gate остаётся `BLOCKED`.

## Конфигурация

Целевые значения MVP:

| Параметр | Значение |
|---|---|
| Go module | `github.com/100bench/OPORA` |
| HTTP router | `github.com/go-chi/chi/v5` |
| Logging | `log/slog` |
| Speech model | `gpt-4o-mini-transcribe-2025-12-15` |
| Reasoning/vision model | `gpt-5.4-mini-2026-03-17` |
| Provider timeout | `20s` hard cap |
| Provider concurrency | `4` |
| Session TTL / capacity | `30m` / `100` |
| Confirmation TTL | `30s` |

Runtime читает закреплённые имена из окружения: `LISTEN_ADDR`,
`OPENAI_API_KEY`, `DEVICE_TOKENS_JSON`, `OPENAI_REASONING_MODEL` и
`OPENAI_TRANSCRIPTION_MODEL`. `.env` загружается явно shell/dev tool, а не
скрытым dotenv parser. `DEVICE_TOKENS_JSON` обязателен; ключ OpenAI может быть
пустым, но тогда `/ready` возвращает 503 и provider paths недоступны. Model IDs
имеют закреплённые defaults, а неутверждённый override приводит к отказу старта.
Секреты не печатаются в логах и не возвращаются health endpoints.

Основные команды обёрнуты Makefile: `make build`, `make run`, `make test`,
`make test-race`, `make vet`, `make coverage` и последовательный `make check`.
Ошибка любого теста или coverage gate распространяется наружу.

Обычный CI запускает offline `make check` и lint с пустым OpenAI key; live calls
не входят в workflow по умолчанию.

`health` сообщает только, что процесс жив. `ready` без сетевого вызова проверяет
локальную provider-конфигурацию; он не доказывает валидность ключа, доступность
закреплённой модели или upstream API.

Для Docker сначала экспортируйте уже разобранные shell values, затем передайте
их через `-e`, например `-e DEVICE_TOKENS_JSON -e OPENAI_API_KEY`. Не используйте
тот же shell-quoted `.env` напрямую через `docker --env-file`: одинарные кавычки
могут попасть в значение буквально. Публикуйте порт только на loopback, например
`-p 127.0.0.1:8080:8080`. Docker image build пока `NOT RUN`.

Default bind — `127.0.0.1:8080`. Для внешнего мобильного подключения нужен
отдельный HTTPS ingress/termination; текущий локальный gateway не является
production multi-user deployment.

## Стиль реализации

- Код и идентификаторы — на английском, документация продукта — на русском.
- Нормальная обработка ошибок вместо panic в request path.
- Зависимости передаются явно; часы и provider clients подменяются в тестах.
- Domain/policy rules детерминированы и не импортируют HTTP/OpenAI packages.
- App/handler отвечает за transport validation, service/use case — за
  orchestration, domain/policy — за инварианты, adapter — за внешние протоколы.
- Форматируйте Go через `gofmt`; не делайте массовых нерелевантных правок.
- Не удаляйте, не пропускайте и не ослабляйте тесты ради зелёного результата.
- Меняйте только относящиеся к задаче файлы и не смешивайте изменение поведения
  с широким рефакторингом.

Если меняется API, модель, лимит, переход состояния или запрет безопасности,
синхронно меняются тесты, OpenAPI, соответствующий документ и `STATUS.md`.

## Работа с данными разработчика

Форматные тестовые аудио, изображения и деревья должны быть синтетическими.
Реальные адресные книги, номера, пароли, OTP и платёжные данные использовать
нельзя. Исходные production-аудио, изображения, деревья доступности и
транскрипции запрещено выгружать или записывать для отладки даже вне
репозитория.

Отдельно утверждённый live-evaluation corpus допустим только при явном согласии,
ограниченном доступе и в специально контролируемом месте вне репозитория; его
использование подчиняется плану live-оценки из [TESTING.md](TESTING.md). Для
обычной отладки не включайте дамп body: используйте размеры, хеши синтетических
фикстур, статусы и trace IDs.
