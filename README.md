# Опора

Опора — проект безопасного голосового помощника для объяснения интерфейса
Android. Пользователь может передать короткую аудиокоманду и явно разрешённый
снимок или accessibility tree; backend возвращает объяснение, подсветку
элементов и, в строго ограниченных случаях, подготовленное действие.

Сейчас проект находится на фазе **`BACKEND_OFFLINE_VERIFIED`**. Локальный
backend реализован, прошёл offline test/race/vet/coverage/lint/build/smoke
проверки и получил [итоговое независимое одобрение](docs/reviews/implementation-review.md).
Live-модели не проверены, Android-клиент не начат.

## Что входит в MVP

Реализован один локально запускаемый Go backend без БД, Redis и очередей.
Контекст сессии живёт только в памяти и исчезает при перезапуске. Это локальный
gateway для MVP, а не готовый multi-user сервис.

Разрешены только два безопасных действия:

- `OPEN_APP` — открыть приложение;
- `PREPARE_DIALER` — открыть номер в системном dialer без совершения звонка.

Оба действия требуют отдельного одноразового подтверждения пользователя со
сроком жизни 30 секунд. Это намеренно консервативное правило MVP.

Offline policy распознаёт ограниченный набор явных русских команд: открыть или
запустить настроенное приложение, подготовить dialer для локального избранного
контакта и показать однозначно найденный элемент. Поддерживаются настроенные
aliases и несколько простых русских падежных форм. Это не универсальный NLU;
прочие объяснения и транскрипция требуют provider path.

Помощник не нажимает произвольные элементы, не отправляет сообщения, не
проводит платежи и не вводит пароли или OTP. Координаты не являются контрактом
управления: подсветка привязывается к стабильному элементу текущего экрана.
Избранные приложения и контакты передаются как непрозрачные `app_ref` /
`contact_ref`, подписи и опциональные aliases — без адресной книги и номеров
телефонов. Foreground package допустим
как контекст текущего экрана, но не как произвольная цель действия. Защищённые
запросы используют per-device bearer token; device ID определяется backend, а
не принимается на доверии из тела запроса.

URI-подобные target refs и очевидные phone/URI-значения в contact metadata
отклоняются, но эта проверка не является универсальным обнаружением
персональных данных. Текст и голос пользователя могут содержать PII.

## Быстрый старт

Нужны Go `1.26.3` и локально установленный `golangci-lint`. Сначала проверьте
репозиторий:

```sh
make build
make test
make test-race
make vet
make coverage
make check
make lint
```

Приложение не загружает `.env` автоматически. Скопируйте шаблон, явно загрузите
его в shell и сгенерируйте bearer token локально — не публикуйте его в чате,
issue или логах:

```sh
cp .env.example .env
set -a; . ./.env; set +a
DEVICE_TOKEN="$(openssl rand -hex 32)"
export DEVICE_TOKENS_JSON="$(printf '{"dev-device":"%s"}' "$DEVICE_TOKEN")"
make run
```

`DEVICE_TOKENS_JSON` обязателен для старта. `OPENAI_API_KEY` можно оставить
пустым для health и детерминированного offline flow: `/health` вернёт `200`, а
`/ready` — `503`; provider-backed объяснения и транскрипция будут недоступны.
`/ready` проверяет только локальную конфигурацию и не подтверждает, что ключ,
модель или upstream реально доступны.

По умолчанию сервер слушает только `127.0.0.1:8080`. Не выставляйте его наружу
как plain HTTP. Для внешнего мобильного клиента нужны отдельно спроектированные
HTTPS termination, сеть и эксплуатационная аутентификация.

Не помещайте настоящий ключ или device token в коммит, аргументы команд, снимки
экрана или логи. Клиент никогда не должен получать ключ провайдера.

## Ограничения входов

- аудио: WAV PCM, 16 kHz, mono, 16-bit, не длиннее 30 секунд и не более 1 MiB;
- изображения: JPEG/PNG, не более 5 MiB и 4 MP;
- accessibility tree: не более 500 узлов и 256 KiB;
- сессии: idle TTL 30 минут, максимум 100 активных сессий;
- подтверждения: TTL 30 секунд;
- запрос к провайдеру: максимум 20 секунд, не более 4 одновременно.

Исходные аудио, изображения, accessibility tree и транскрипты не должны
попадать в постоянные файлы или логи. При этом речь может содержать персональные
данные, поэтому продукт не обещает анонимность.

После TTL запись сразу становится недоступной, но очистка памяти выполняется
лениво при следующей операции/callback или перезапуске процесса. Это не гарантия
физического стирания ровно через 30 минут.

должны переноситься в Опору или маскироваться заявлением о готовности.
